# ListenLoop · AI 精听训练器

> 面向**严肃外语学习者**的影视级逐句精听系统（Android / Flutter）。
> 本仓库是项目的**真源快照**：Obsidian 知识库的核心文档 + 已交付代码快照，用于与外部 AI 协作者（GPT 级模型）做架构与产品评审。

---

## 一、这是什么项目

ListenLoop 把「一段影视原声」拆成**毫秒级句轴**，让用户逐句精听、复读、跟读，并用 AI 拆解音变规律、用记忆卡对抗遗忘。
核心闭环：**导入 → 逐句精听 → 音变解析 → 记忆卡沉淀 → 间隔复习**。

当前产品状态（2026-09-23）：Android 真机可跑，已上双链路（在线大模型 + 离线兜底）。

## 三、当前技术事实（2026-09-23 实测，非推测）

### 模型服务（已统一为小米 MiMo，手机可脱离 PC 独立运行）

| 能力 | 端点 / 模型 | 实测表现 |
|:--|:--|:--|
| 对话 / 翻译 | `https://api.xiaomimimo.com/v1` · `mimo-v2.6-flash` | 拉模型列表 0.28s；字幕批量翻译 6.9s（严格 JSON）；伴学问答 7.5s |
| 回退链 | `mimo-v2.6-flash` → `mimo-v2.6-pro` → `mimo-v2.5` | 同厂同 key，仅换档位 |
| 语音识别 | `mimo-v2.5-asr` | **0.60s** 返回转写；**无**标准 `/v1/audio/transcriptions`（实测 404），必须走 chat 风格接口 |
| 语音合成 | `mimo-v2.5-tts` | 冷启动 11.5s；热态短句 **0.95s**、200 字符 **3.4s**；**限时免费**；音色白名单 |

### 网络约束（决定了架构选型）

- PC 挂着 mihomo 全局代理（`127.0.0.1:7890`），因此 PC 侧可达 openrouter / cloudflare / nvidia 等墙外免费线路；**手机侧这些全部不可达**（实测 HTTP 000），而国内端点（MiMo、ModelScope、硅基流动、智谱、火山方舟）手机全部可达。
- PC 与手机**不在同一网段**（PC `192.168.152.156` / 手机 `192.168.2.12`），局域网直连模式目前不通；USB 中继（`adb reverse`）可用但不持久。

### 已修复的关键缺陷

- **长视频放不出来**：B 站 `<video>` 元素始终 1.3s 出现，但 metadata 就绪时间随片长线性增长（4 分钟片 1.3s，2h45m 片 **13.5s**）。旧实现对两者用同一个 20s 硬超时等，长片必然失败。已改为两阶段就绪（元素出现即解除阻塞，命令内部等 metadata）。
- **AI 管家是"假在线"**：两个 bug 叠加——服务未注入偏好（`prefs == null` 读不到配置）＋模型 id 写死在网关不存在的名字上，导致 App **一次真实请求都没发过**，全程走本地中文模板。

### 测试基线

`dart analyze lib/ test/` 0 issue；`flutter test` **256 项通过**。

## 五、产品优先级（2026-09-23 定调，最高约束）

> **"听"是核心功能；AI 陪练与 Anki 闪卡是附属功能（额外的小创意）。**

| 层级 | 内容 | 归属 |
|:--|:--|:--|
| **核心** | 逐句精听本体（句轴 / 播放 / 定位 / 复读 / 盲听 / 听写 / 同速背诵）、训练方法学（四步法） | `EPIC-01` ＋ 05 文档 |
| **支撑** | 影视制课管线（核心的素材供给） | `EPIC-02` |
| **附属** | 听伴（AI 对话与语音）、Anki 闪卡、3 分钟快检 | `EPIC-03` / `EPIC-04` |
| **远期** | 全自主学习运行时 | `EPIC-05` |

**核心的判定标准**（两条都满足才算核心）：① 直接作用于"听清一个句子的声音"；② 断网后仍能完整使用。

**交互红线**：核心操作不得深于 1 层；附属只能二级入口；附属失败不得阻塞核心；**不得用 TTS 合成音替代原片句轴**（那是拿附属冒充核心）。

完整基准见 `docs/02_工程架构与系统设计/08_核心精听优先_产品优先级定调.md`。
