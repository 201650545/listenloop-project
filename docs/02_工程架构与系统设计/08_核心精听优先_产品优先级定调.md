# 08 · 核心精听优先：产品优先级定调

> **定调人**：郭老师｜**定调时间**：2026-09-23
> **定调原文**：「其实"听"是我们的核心功能，其他我跟你说的 AI 还有 ANK，是附属的功能，就是额外的小创意。」

---

## 一、一句话结论

**ListenLoop 的核心是「听」；AI 陪练（听伴）与 Anki 闪卡是附属能力，不是主线。**
一切排期、交互层级与视觉权重，都必须服从这条分层。此前几轮设计把 AI 与 Anki 摆在了过高的位置（详情页、面板 tab、独立卡片），**需要整体降级复位**。

---

## 二、分层映射（沿用既有 EPIC 编号，不新造）

| 层级 | 归属 | 说明 |
|:--|:--|:--|
| **核心层** | `EPIC-01 核心播放与分句引擎` | 逐句精听本体：句轴、播放、定位、复读、盲听、听写、同速背诵 |
| **支撑层** | `EPIC-02 多语言影视制课管线` | 不是核心体验，但是核心的**供给**——没有素材就没有精听。列为高优先支撑，但不与核心争交互中心 |
| **附属层** | `EPIC-03 AI 智能管家与特训法`、`EPIC-04 纯英文 Anki 记忆体系` | 「额外的小创意」。可降级、可延后、断网可失效 |
| **远期层** | `EPIC-05 全自主学习运行时` | 依赖前三层数据沉淀，最后做 |

## 三、判定标准：一个功能算核心还是附属？

两个问题，**两条都答"是"才算核心**：

1. **它是否直接作用于「听清一个句子的声音」？**
   —— 让用户听得更准、更反复、更可对照，就是核心。让用户"多知道点东西"的，是附属。
2. **断网之后它是否仍能完整使用？**
   —— 核心必须**离线完整可用**（播放、句轴、字幕、听写判定、SM-2 调度全在本地）。附属允许降级或失效。

按此判据复检既有功能：

| 功能 | 核心/附属 | 依据 |
|:--|:--|:--|
| 逐句播放、句轴定位、变速、复读、滑栏 | **核心** | 直接作用于听；完全离线 |
| 盲听（无字幕通听 N 遍） | **核心** | 直接作用于听；完全离线 |
| 听写（句级录入 + 词级 diff） | **核心** | 直接检验"听清了多少"；diff 可全本地 |
| 同速背诵（录音 + ASR + 时长比） | **核心** | 直接作用于听；ASR 不可用时降级为自听回放 |
| 音变解析（连读/弱读/失爆/闪音标注） | **核心**（标注）／附属（AI 解释文本） | 标注规则可本地；深度解释依赖 AI |
| 制课（链接/文件 → 句轴课程） | **支撑** | 核心的供给链，不是核心体验本身 |
| 听伴对话、语音问答、回复朗读 | **附属** | 锦上添花；离线即失效 |
| Anki 闪卡、复习队列、弱项雷达 | **附属** | 记忆管理；本地可用但不直接作用于"听" |
| 3 分钟快检 | **附属** | 快速回访工具 |
| 尚雯婕四步法训练轨道 | **核心** | 四步（盲听→听写→查证→背诵）本质是**听力训练方法学**，直接作用于听 |

> ⚠️ **重要澄清**：`05_尚雯婕精听法产品化设计.md` 虽然编号排在 AI 之后，但它描述的是**训练方法学**，属**核心层**，优先级高于 06/07。此前把它和 AI/Anki 一起当成"AI 功能"是分类错误。

---

## 四、交互红线（防止附属再次挤占核心）

1. **首屏与视觉中心只留给"听"**。听伴不得占据精听页的主操作位；它的入口保持轻量（当前为左上角图标，合格）。
2. **核心操作不得深于 1 层**。播放/暂停/上一句/下一句/变速/复读/切模式，必须直接在精听页上；任何进二级页才能完成的听操作都算设计事故。
3. **附属只能二级入口**。闪卡管理走 Library 二级；听伴走抽屉。不做底部 tab 增位（会动 L1 导航，成本高于收益）。
4. **附属失败不得阻塞核心**。AI 不可用、TTS 冷启动、ASR 超时——一律降级，核心链路照常可听、可写、可判、可调度。
5. **不把"能听"的能力外包给 AI**。凡是原声句轴已经能提供的能力（原句回放、句间定位），不得改用 TTS 合成音替代——那是拿附属冒充核心。

## 五、重排后的执行顺序

| 序 | 优先级 | 任务 | 层级 |
|:--|:--|:--|:--|
| P0 | 最高 | **核心听感硬化**：句轴精度、切句竞态、播放容错（长视频两阶段就绪已落地）、复读与盲听可用性、音变标注的本地规则 | 核心 |
| P1 | 高 | **听写引擎**：句级录入 → 段级集中批改 → 词级 LCS diff 三色标注 → 错误分类（客观 diff 类型 + 训练原因标签两层） | 核心 |
| P2 | 高 | **同速背诵**：录音 → MiMo ASR → 归一化词级准确率 + 时长比判定 | 核心 |
| P3 | 中 | 训练周期状态机（四步训练轨道、进度与播放进度分离、跨天续训） | 核心 |
| P4 | 中 | 听伴重构：命名统一 + 三主动作（拆音变 / 听写这句 / 跟读核对） | 附属 |
| P5 | 中低 | 闪卡搬到 Library 二级 + 日队列（新卡 5 / 复习 30） | 附属 |
| P6 | 低 | 弱项统计、快检重构、10 篇训练营 | 附属 |

**关键**：P0–P3 全部属于核心，且**都不依赖 AI**。这是本轮排序的最大意义——先把"听"这件事本身做到无人能及，附属功能建立在它之上，而不是反过来。

## 七、已采纳的外部评审结论（2026-09-23 镜像站 GPT Extended 首轮）

按新优先级重新归位——**核心相关立即改，附属相关只登记**：

**立即改（核心）**
1. **听写：句级录入、段级集中批改**，不逐句揭答案（原设计违背"写完全篇再对原文"的方法本体）。
2. 「漏掉功能词」不得直接断言为"弱读吞音"，UI 只能写"可能与弱读有关"；**客观 diff 类型与训练原因标签分两层**。
3. **大小写、标点默认不计错**；`I am / I'm` 之类先归一化，否则三色 diff 会制造假错误；无法可靠对齐时明说"无法精确定位"，不伪造诊断。
4. 四步法与逐句精听**并存不替换**（四步法本身排除影视剧，不能拿它替掉核心素材场景）。
5. 「完成 10 篇可作工作语言」**不得作为产品承诺**，只能写"完成 10 个训练周期"。

**登记待改（附属）**
6. 听伴：命名选「听伴」；首屏只留三主动作；**"听写这句"必须播原片 snippet 而非 TTS**；「跟读评分」改名「跟读核对」并明示"发音细节无法可靠评分"。
7. 闪卡：入口走 Library 二级并显示"今日待复习 N"；参数改 新卡 5 / 复习 30 / 毕业 3d / leech 累计 6 次 Again；弱项加权**只能在已到期卡之间排序**，不得提前拉卡（会破坏 SM-2）。

## 八、一个待修正的实现缺陷（本轮自查发现）

`AiGovernorService.generateQuizQuestions()` 生成的 Q2/Q3：选项**未打乱**且 `correctIndex` 恒为 `0`，正确项是固定模板（如"伴随自然弱读与后接词的连贯滑音…"），**与真实音频无关**。即答案位置恒定、内容与当前句脱钩 —— 该快测当前不是可靠检测，属**伪诊断**。

按新分层，这是附属功能（P6），但**伪诊断会污染用户对"弱项/闪卡/诊断"整套闭环的信任**，因此要么尽快按"有证据才出题"重构，要么先下线关联文案，不允许继续以"尚雯婕"名义输出。
