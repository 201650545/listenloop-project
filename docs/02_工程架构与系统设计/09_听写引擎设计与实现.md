## 一、为什么先做它

四步法（盲听 → 听写 → 查证 → 背诵）里，**听写是唯一的"硬证据"环节**：它把"我好像听懂了"变成"我漏了哪几个词"。
仓库此前的三个事实决定了它的优先级：

1. 「尚雯婕 3 分钟限时精听法」实际是 3 道选择题，**与四步法无关**，且题目正确项是固定模板（伪诊断）；
2. 四步法里的**听写与同速背诵完全不存在**；
3. 闪卡与弱项统计都缺"错误证据"的来源——听写正是这个来源。

且听写**不依赖任何 AI**：判定纯本地，断网照常可用，符合核心层判据。

## 二、交互契约（已实现并被测试锁定）

| 契约 | 实现方式 | 测试 |
|:--|:--|:--|
| **句级录入、段级集中批改** | 进入段落后逐句写，提交本段前**不显示任何原文** | `dictation_screen_test`：录入阶段一个原文词都不泄露 |
| **留空合法** | 每句可点「没听出来」，与"写错"区别对待，不要求编答案 | `dictation_session_test`：留空的句子 isBlank 且不算不可靠 |
| **必须交代完才能提交** | 每句要么有内容、要么标留空，否则提交按钮禁用 | `dictation_screen_test`：没有交代完全时提交按钮不可用 |
| **批改后禁止修改** | `reviewing` 阶段 `setText` 静默失效；输入框消失 | `dictation_session_test`：批改后禁止再改内容 |
| **不读 TTS** | 复用精听页同一个 `SentencePlayerController`，只播原片句轴 | 红线见 08；用 TTS 读原句＝拿附属冒充核心 |
| **对齐不可靠就降级** | `uncertain` 时只给整体结果与两行纯文本，不给逐词着色 | `dictation_engine_test`：整句几乎不对时标记 uncertain |

## 三、两层结构：能断言 vs 只能提示

这是本引擎最重要的设计约束。外部评审明确指出：把「漏掉功能词」直接解释成「这是弱读吞音」**因果过强**——用户可能只是没注意，规则也没有分析真实音频。

### 第一层：客观 diff 类型（**可以断言**）

| 类型 | 触发条件 |
|:--|:--|
| `matched` | 完全一致 |
| `missing` | 原文有、用户没写 |
| `extra` | 原文没有、用户写了 |
| `spelling` | 位置对上、词不同，但相似度 ≥ 0.7（Levenshtein） |
| `morphology` | 一方是另一方的词干，差一个词尾（`walked`/`walk`、`book`/`books`） |
| `merged` | 两词写成一词（`a lot` → `alot`） |
| `split` | 一词写成两词（`alot` → `a lot`） |
| `replaced` | 位置对上但词不同，相似度 < 0.7 |

### 第二层：训练原因提示（**只能提示**）

全部经 `LLStrings.dictationCause()` 统一出口，**文案自带「可能」**：
`可能与弱读有关` / `可能与连读有关` / `可能与失爆有关` / `可能与闪音有关`。

触发规则（均为文本级近似，**不是音频分析**）：

| 提示 | 规则 |
|:--|:--|
| 弱读 | 该词属于闭类功能词表（冠/介/代/助/连） |
| 连读 | 该词以辅音结尾，且**下一个原文词**以元音开头 |
| 失爆 | 该词以塞音（t/d/p/b/k/g）结尾，且下一词以辅音开头 |
| 闪音 | 词形匹配「元音 + 单个 t/d + 元音」（如 `water`、`better`） |

> ⚠️ **能力边界**：这些提示来自**文本规则**，不是对音频的声学分析。产品文案与 UI 都必须保持"可能"口径，禁止升级为确定结论。要真正判定音变，需要词级时间戳或音素对齐——仓库目前**未证明** MiMo ASR 提供该能力，故不纳入 V1 依赖。

## 四、两个指标决策（都踩过坑）

### 1. 准确率的分母必须包含「多写词」

初版写成 `errorCount = 原文词数 - 正确词数`，结果**完全不计多写**：用户随手多写一堆词反而拿满分（测试直接抓出来了）。

现口径：

```
准确率 = 正确词数 / (原文词数 + 多写词数)
```

其中 `多写词数 = 用户所写词数 - 命中词数`（命中词必然两侧共有）。
分母同时惩罚「漏」与「多」，与直觉一致。段级沿用同一口径。

### 2. 整句留空 ≠ 对齐不可靠

初版把"错误率 > 60%"一律判为 `uncertain`，导致**整句留空（错误率 100%）被误判为对齐混乱**，而留空恰恰是原方法允许的合法答案。

现规则：仅在**用户确实写了内容**且错误率过高时才降级：

```
uncertain = 用户所写词数 > 0 && 错误处数 / (原文词数 + 多写词数) > 0.6
```

## 五、归一化规则（防假错误）

| 规则 | 说明 |
|:--|:--|
| 大小写 | 全部小写，**不产生错误** |
| 标点 | 一律视为分隔符；中文标点、弯撇号先归一化为 ASCII |
| 缩写 | 两侧统一展开：`I'm`→`i am`、`don't`→`do not`、`let's`→`let us`、`gonna`→`going to`…；未登记的 `n't` 按「词干 + not」兜底展开 |

不做归一化的话，`I'm` 与 `I am` 会被判成两个错误——三色标注会被假错误淹没。

## 六、状态机

```
entering（录入）
   ├─ setText / markUnknown（逐句）
   ├─ goTo / next / previous（只移动光标，绝不揭答案）
   └─ submitSegment() ──► reviewing（批改）
reviewing（批改）
   ├─ lineResultAt(i) 取逐句结果
   ├─ redoSegment() ──► 回到 entering 并清空本段
   └─ next/previousSegment()（保留已批改结果）
```

* 段长默认 **5 句**（`DictationSession.segmentLength`，构造可配）。
* **训练进度与播放进度分离**：`trainingProgress` = 已完成批改的段数 / 总段数，与播放位置无关（05 文档指出此前只有播放进度）。
* 切回已完成段仍显示批改结果，不丢。

## 七、代码与测试落点

| 文件 | 职责 |
|:--|:--|
| `lib/training/dictation_engine.dart` | 纯函数引擎：归一化、LCS 对齐、错误分类、原因提示、段级聚合。**零依赖、零网络** |
| `lib/training/dictation_session.dart` | 会话状态机：段切分、录入态、提交锁、段间流转 |

| `lib/screens/listening_screen.dart` | 顶栏加入口 `Key('dictation-button')` —— **一级页直达，不埋二级** |

测试：`test/training/dictation_engine_test.dart`、`test/training/dictation_session_test.dart`、`test/screens/dictation_screen_test.dart`。

> 📌 写听写断言时**必须**用能扫 `RichText` 的匹配器（参见 `dictation_screen_test.dart` 的 `_screenContains`）。对照行是逐词着色的 RichText，`find.text` 匹配不到，用它写"不泄露原文"会得到**假通过**。
