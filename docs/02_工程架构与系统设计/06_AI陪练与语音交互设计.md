# 06 AI 陪练与语音交互设计 (AI Companion & Voice)

> 本文回答三件事：**叫什么名字**、**具体做什么**、**语音能力怎么落地**。第三部分全部基于 2026-09-23 的真实实测数据，不是可行性推测。

---

## 一、 命名：「AI 智能管家」的问题与替换方案

### 1. 为什么难听

- **四个字里三个是空词**：「智能」「管家」都是可以贴到任何产品上的话术，不承载信息
- **与品牌无关**：ListenLoop 的内核是「精听循环」，而"管家"暗示的是家政式代办，语义方向相反
- **气质不对**：这是给认真练听力的人用的工具，不是卖课的落地页

### 2. 候选方案

| 名称 | 理由 | 风险 |
| :--- | :--- | :--- |
| **「听伴」** | 与"精听"同源，两字有陪伴感；"伴"恰好是陪练、陪听、陪伴 | 略文艺 |
| **「陪练」** | 功能直白（听力/口语陪练），用户零学习成本 | 偏健身/驾校联想 |
| **「私教」** | 直接、有专业感 | 略贵气，与"免费/自持"的产品调性有张力 |
| **「Loop」** | 直接沿用品牌词 | 与 App 名重复 |
| **「耳语」** | 意象贴合"听" | 功能不明，容易被误解为语音助手 |

> [!TIP]
> **推荐「听伴」**。若嫌"伴"字软，退一步用「陪练」。命名一旦定下，术语要在全 App 统一（弹层标题、Library 卡片、设置页分区、以及 `LLStrings`）。

## 二、 功能设计：从「三合一抽屉」改为「以当前句为中心」

### 1. 现状问题

现在是一个底部弹层塞三个 tab：

| 现有 tab | 问题 |
| :--- | :--- |
| 3分钟快测 | 3 道选择题，与精听过程脱节；且盗用"尚雯婕"名号（见 05 文档） |
| AI 伴学讨论 | 一个空白聊天框 —— **用户在精听时最大的困难是"不知道该问什么"**，给空白框等于把负担丢回给用户 |
| Anki 闪卡 | 闪卡管理与复习被塞在抽屉第三页，与"复习需要独立空间"矛盾（见 07 文档） |

### 2. 新结构

**核心转变：从「聊天工具」变成「当前这句的陪练」** —— 所有动作都锚定"我正在听的那一句"。

```
┌─ 听伴 ───────────────────────────┐
│ 当前句                            │
│   Pick it up and put it on...     │
│   捡起来放到桌上                   │
│   [▶ 重听原声]   [🔁 循环]         │
├─ 快捷动作（取代空白输入框）────────┤
│  🔊 拆音变     📐 讲语法           │
│  ✍️ 造句       🎧 听写我           │
│  🎤 跟读评分   ⭐ 加入闪卡          │
├─ 对话区（发起后展开）──────────────┤
│  ...AI 回复（可点喇叭朗读）...      │
├─ 自由输入 ────────────────[🎤]────┤
└──────────────────────────────────┘
```

**六个快捷动作的定位**（前四个是"AI 讲给你听"，后两个是"你讲、AI 评"）：

| 动作 | 做什么 | 技术依赖 |
| :--- | :--- | :--- |
| 🔊 拆音变 | 连读／弱读／闪音／失爆逐条拆解（对齐 `03_纯英文Anki与AI机制设计.md` 的四大音变） | LLM（已有） |
| 📐 讲语法 | 该句结构、固定搭配、文化语境 | LLM（已有） |
| ✍️ 造句 | AI 给 3 个同类场景例句，再让用户仿写 1 句并批改 | LLM（已有） |
| 🎧 **听写我** | AI 朗读当前句（可变速）→ 用户写 → 批改 | **TTS + 文本 diff** |
| 🎤 **跟读评分** | 用户朗读 → ASR 转写 → 与原文比对相似度 + 时长比 | **ASR + 录音** |
| ⭐ 加入闪卡 | 落库为 Anki 卡（纯英文卡面，见 07） | 已有 |

> 后两个动作让"陪练"名副其实：**AI 不再只是输出文字，而是能听、能评、能读**。

### 3. 语音交互（用户明确要求的两点）

1. **输入框加语音**：长按麦克风说话 → 松手转写 → 自动发送（微信式交互，零学习成本）
2. **AI 回复可朗读**：每条回复下方一个喇叭按钮；点击后**分句合成、边合成边播**（长回复不必等整段合成）

## 三、 语音技术实现（2026-09-23 实测数据）

### 1. 结论先行

**小米 MiMo 一套就能覆盖 ASR + TTS，且与当前已配的模型同 key、同端点、手机国内直连**，不需要额外渠道，也不需要 PC 中继。

| 能力 | 模型 | 端点与格式 | 实测延迟 | 成本 |
| :--- | :--- | :--- | :--- | :--- |
| **ASR** | `mimo-v2.5-asr` | `POST /v1/chat/completions`，`messages[0].content = [{"type":"input_audio","input_audio":{"data":<base64>,"format":"mp3"}}]` | **0.60s** | 按 token 计 |
| **TTS** | `mimo-v2.5-tts` | `POST /v1/chat/completions`，`messages=[{"role":"assistant","content":<文本>}]` + `audio: {"format":"mp3","voice":"Chloe"}` → 返回 `choices[0].message.audio.data`（base64 mp3） | 短句 **0.95~1.43s**；200 字符 **3.40s**；中文配音色 **2.20s** | **限时免费** |

### 2. 关键坑（实测踩到，务必注意）

> [!WARNING]
> 1. **MiMo 没有标准 OpenAI 语音端点**：`POST /v1/audio/transcriptions` 返回 **404**（openresty）。ASR 与 TTS **都必须走 `/chat/completions`**，靠 `input_audio` / `audio` 字段区分。
> 2. **TTS 首次调用 11.47s**（冷启动），第二次起 1~3s。**不要在用户点"朗读"时才首次初始化** —— 可在进入课程页时预热一次。
> 3. **音色是白名单**：`冰糖 / 茉莉 / 苏打 / 白桦 / Mia / Chloe / Milo / Dean`。传入其它值会被忽略并回退默认（英文建议 Mia/Chloe/Milo/Dean，中文用冰糖/茉莉）。
> 4. 网关侧对 MiMo TTS 有**余额警戒**：mimo 渠道余额 ≤20% 时会被 `quota_guard` 拦截 —— 若 App 直连则不受此限制，但也就没有这层保护。

### 3. 网关已有的语音链（备选，不是首选）

网关 `:3100` 已编排好两条链（2026-09-22）：

- `voice-tts`：**MiMo-TTS**（限时免费）→ **Edge-TTS**（本地子进程，免费无限，需 PC 的 `.venv-edge`）→ mistral voxtral-mini-tts
- `voice-asr`：multipart 转发 `/v1/audio/transcriptions`，按链回落

**取舍**：走网关能拿到 Edge-TTS 的音色与无限额度，但**必须插线或同一局域网**，与"手机独立可用"冲突。故 **App 直连 MiMo 为准，网关链保留给 PC 场景**。

### 4. 建议的落地形态

| 场景 | 方案 |
| :--- | :--- |
| 输入框语音 | 录音 → 16k mp3 或 m4a → base64 → `mimo-v2.5-asr` → 填入输入框（可编辑后再发送） |
| 朗读 AI 回复 | 按标点**分句** → 逐句 `mimo-v2.5-tts` → 队列播放；首句 1s 内可出声，长回复无需等待 |
| 听写我 | `mimo-v2.5-tts` 出题（可选 0.75× 变速）→ 用户写 → 复用听写的词级 diff |
| 跟读评分 | 录音 → ASR → 相似度 + 时长比（与 05 文档的同速判定同一套指标） |

## 四、 实现拆解

| 阶段 | 内容 | 依赖 |
| :--- | :--- | :--- |
| **V1** | 命名统一 + 六动作重构（前三项走现有 LLM） | 无 |
| **V2** | 输入框麦克风（录音 → ASR → 发送） | 录音权限、MiMo ASR |
| **V3** | 回复朗读（分句 TTS + 播放队列 + 预热） | MiMo TTS |
| **V4** | 听写我 / 跟读评分（复用 05 文档的 diff 与同速判定） | V2、V3 |

## 五、 风险

1. **录音权限与隐私**：语音是敏感数据。建议**默认不保存录音**，仅在本地内存中用于转写，转写完成即丢弃；如需保存（用于跟读对比）必须显式开关。
2. **TTS 是否长期免费**：网关注释写明"价格限时免费"。**不要把产品体验建立在限时免费上** —— 保留可切换到 Edge-TTS（PC 中继）或系统 TTS 的降级路径。
3. **ASR 对带口音的英语**：MiMo 是中文厂商模型，英文转写准确率需真机抽测（本轮只测了一道合成语音，过于干净，不代表真实跟读场景）。

## 六、 需要拍板

1. 名字定哪个：**听伴** / 陪练 / 私教 / 其它？
2. 六个快捷动作是否都要，还是先做「拆音变 + 听写我 + 跟读评分」这三个最能体现差异化的？
3. AI 回复**默认自动朗读**还是**点击才读**？（默认朗读更沉浸，但会打扰旁人）
4. 录音是否允许本地留存（用于跟读回放）？
