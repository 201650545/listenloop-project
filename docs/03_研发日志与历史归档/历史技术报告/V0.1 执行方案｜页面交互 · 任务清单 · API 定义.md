# ListenLoop V0.1

## 页面交互说明 + 技术任务清单 + 数据结构/API 定义

---

# 0. 文档目标

V0.1 只验证一个核心体验：

> **用户导入真实英语内容后，可以非常顺畅地按句听原声、循环、看英文、看中文，并快速切换上一句/下一句。**

V0.1 不以“功能丰富”为目标，而以：

**导入成功率 + 切句质量 + 单句循环体验**

为核心。

---

# 1. V0.1 整体系统流程

```text
用户
 ↓
选择内容来源
 ↓
YouTube URL / 本地音频视频
 ↓
创建 Media
 ↓
获取字幕 / Whisper 转录
 ↓
字幕清洗
 ↓
句子合并与切分
 ↓
生成 Sentence[]
 ↓
整句中文翻译
 ↓
进入精听页
 ↓
根据 start_ms / end_ms 控制原声播放
```

注意：

### YouTube

V0.1 推荐采用：

```text
YouTube 原播放器
+
Sentence 时间轴控制
```

也就是说：

**听到的仍然是 YouTube 视频中的真实原声。**

数据库不需要保存一个单独的 YouTube MP3。

### 本地音频/视频

使用用户提供的：

```text
MP3
M4A
WAV
MP4
```

作为真正的媒体源。

Whisper 只是负责：

```text
音频 → 文本 + 时间戳
```

而不是替换原声。

# 7. 单句播放逻辑

每一个 Sentence 包含：

```text
start_ms
end_ms
```

例如：

```text
start_ms = 12420
end_ms = 16850
```

点击播放：

```text
seek(12420)
 ↓
play()
 ↓
监听 currentPosition
 ↓
>= 16850
```

然后判断：

```text
repeat_current < repeat_count ?
```

如果是：

```text
repeat_current += 1
seek(start_ms)
play()
```

如果否：

```text
pause()
repeat_current = 0
```

---

# 8. 无限循环

```text
repeat_mode = infinite
```

则：

```text
currentPosition >= end_ms

→ seek(start_ms)

→ play()
```

直到用户：

```text
暂停
下一句
上一句
关闭无限循环
```

---

# 9. 防止句尾被截断

不要严格：

```text
start_ms → end_ms
```

实际播放范围建议：

```text
playStart =
max(0, start_ms - pre_buffer_ms)

playEnd =
min(duration, end_ms + post_buffer_ms)
```

初始：

```text
pre_buffer_ms = 150

post_buffer_ms = 200
```

后面根据体验调整。

---

# 10. 上一句

点击：

```text
currentIndex -= 1
```

然后：

```text
load sentence
seek(sentence.start_ms)
```

默认不强制自动播放。

可以设置：

```text
auto_play_after_navigation = true/false
```

V0.1 推荐：

**如果当前正在播放，则切句后继续播放。**

如果原来暂停，则保持暂停。

---

# 11. 下一句

规则与上一句一致。

最后一句点击下一句：

```text
已经是最后一句
```

不要跳回第一句。

# 23. 初版切句算法

输入：

```text
cue[i]
cue[i+1]
```

计算：

```text
gap =
cue[i+1].start_ms -
cue[i].end_ms
```

满足以下任意情况：

```text
文本以 . ? ! 结束

gap > pause_threshold

当前句已经过长
```

→ 候选切句。

初始参数：

```text
pause_threshold = 700 ms

target_min_duration = 1500 ms

target_max_duration = 9000 ms

hard_max_duration = 12000 ms
```

这些必须做成配置。

不要写死在业务代码里。

# 60. V0.1 技术验收标准

## 单句播放

例如：

```text
start = 10.000s
end = 14.000s
```

实际结束误差目标：

```text
±200ms 左右
```

不能出现：

```text
明显吃掉单词尾音
```

---

## 切句

大部分内容：

```text
一条 Sentence
≈ 一个自然听力单位
```

不是要求 100% 符合语法句。

重点是：

**适合听力训练。**

---

## 翻译

中文必须基于完整英文 Sentence。

不能明显存在：

```text
碎片翻译拼接感。
```

---

## UI

用户在精听页：

常用操作不能超过一次点击：

```text
播放

上一句

下一句

字幕切换

循环
```

# 61. V0.1 产品验收问题

开发完成之后，不要先问：

> UI 漂不漂亮？

首先拿一段 5～10 分钟英语访谈实际练习。

回答下面几个问题：

```text
1. 连续听 20 句话会不会累？

2. 重复一句是不是足够快？

3. 句头有没有被截断？

4. 句尾有没有被截断？

5. 上一句/下一句是否顺手？

6. 什么时候最想打开英文字幕？

7. 什么时候最想打开中文？

8. 自动切句有没有大量“不自然”的情况？

9. 0.75x 是否真的有必要？

10. 用完后是否比普通 YouTube 精听明显轻松？
```

如果第 10 个答案是：

**是。**

那么 V0.1 的核心价值已经被验证。

# 64. 最终 V0.1 架构结论

第一版最值得追求的不是“聪明”。

而是：

**快、稳、顺。**

理想状态是用户点击一句以后：

```text
几乎立即播放
```

听不懂：

```text
再点一下
```

或者系统自动循环。

需要帮助：

```text
打开英文
```

还是不懂：

```text
打开中文
```

听懂以后：

```text
下一句
```

整个过程用户几乎不用：

```text
拖进度条
找字幕
暂停
倒退
重新定位
```

这就是 ListenLoop V0.1 最核心的产品价值。

# 65. 一句话技术定义

ListenLoop V0.1 本质上可以理解为：

> **一个以 Sentence Timeline 为核心数据模型、以真实媒体播放器为核心执行引擎、以语音识别和翻译为内容生成能力的移动端精听系统。**

其中真正的“心脏”不是 Whisper，也不是 AI。

而是：

```text
Sentence
{
  start_ms,
  end_ms,
  english,
  chinese
}
```

只要这一层做对，后面的：

```text
循环

听写

单词高亮

弱点分析

SRS

AI 教练
```

都可以围绕它继续生长。
