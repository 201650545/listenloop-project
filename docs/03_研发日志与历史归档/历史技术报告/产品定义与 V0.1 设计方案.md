# AI 精听训练器｜产品定义与 V0.1 设计方案

## 一、产品名称

暂定名：

**ListenLoop**

中文名可暂定为：

**精听循环 / 句听 / 听懂**

产品名称后续再确定，V0.1 阶段重点是验证产品核心体验。

---

# 二、产品一句话定义

**把真实母语者音视频内容，自动转换成可以逐句循环、双语理解和反复精听的学习材料。**

用户不需要自己剪音频、做字幕、整理句子。

只需要提供一个内容来源，系统自动完成：

**字幕获取 / 语音识别 → 自动切句 → 中英对照 → 单句循环 → 精听训练**

---

# 三、产品定位

ListenLoop 不是普通的视频播放器，也不是传统背单词软件。

它是一款：

> **以真实母语者原声为核心的逐句精听训练工具。**

传统语言学习工具通常解决的是：

* 这个单词是什么意思？
* 这句话怎么翻译？
* 怎么背更多单词？

ListenLoop 重点解决的是：

> **“这句话我明明看得懂，为什么听的时候听不出来？”**

产品重点训练：

**Sound → English → Meaning**

也就是：

**声音识别能力 → 英文理解能力 → 含义理解能力**

---

# 四、核心用户

第一阶段主要面向：

### 1. 英语中级学习者

大致特点：

* 阅读英语基本没问题；
* 看字幕时能理解大部分内容；
* 但关掉字幕后，经常听不懂；
* 对连读、弱读、吞音、不完全爆破等不敏感；
* 想通过 YouTube、Podcast、采访等真实材料提升听力。

这是最核心用户。

---

### 2. 喜欢用真实内容学习英语的人

例如经常看：

* YouTube
* TED
* Podcast
* 新闻
* 访谈
* 影视片段
* 英语课程

他们不希望学习材料都是人为录制的“教材英语”。

他们更需要：

> **真实语速、真实表达、真实口音。**

---

### 3. 有“精听习惯”，但目前操作成本很高的人

目前用户可能需要：

* 暂停；
* 拖进度条；
* 再听；
* 再倒退；
* 打开字幕；
* 查单词；
* 再播放一次。

整个过程非常痛苦。

ListenLoop 的价值就是：

> **把这些机械操作自动化。**

---

# 五、核心问题

用户真正的问题不是：

> “我需要一个双语字幕播放器。”

而是：

> **“我需要快速定位自己听不懂的句子，然后反复听，直到我的耳朵真正识别出它。”**

因此产品核心不是“字幕”。

而是：

# **句子级音频控制。**

所有其他功能都围绕这件事展开。

---

# 六、产品核心价值

ListenLoop 的三个核心价值：

## 价值 1：真实原声

尽可能使用：

* 原视频声音；
* 原 Podcast 声音；
* 用户自己的 MP3 / MP4；

而不是 AI TTS。

用户学习的是：

> **真实母语者到底是怎么把这句话说出来的。**

---

## 价值 2：一句一句听

系统自动把内容整理成：

```text
Sentence 01
00:12.4 → 00:16.8

I didn't realize how difficult it was.

我当时没意识到这件事有多困难。
```

用户点击：

**循环 3 次**

播放器只播放：

```text
12.4s → 16.8s
```

然后重新回到：

```text
12.4s
```

而不是让用户手动拉进度条。

---

## 价值 3：字幕逐步揭示

ListenLoop 不鼓励用户从第一遍开始就盯着字幕。

理想学习流程：

```text
裸听
 ↓
裸听
 ↓
英文字幕
 ↓
中英字幕
 ↓
再裸听
```

最终目标不是：

> 看懂字幕。

而是：

> **重新听的时候，可以直接从声音中理解。**

---

# 七、核心产品原则

## 原则 1：Audio First

首先服务“听”。

字幕只是辅助。

---

## 原则 2：Sentence First

用户主要操作对象不是：

“整段视频”。

而是：

“当前这一句话”。

---

## 原则 3：真实声音优先于 AI 声音

除非特殊场景，否则不使用 TTS 替代原音频。

---

## 原则 4：学习流程自动化

尽量减少：

* 暂停；
* 拖动；
* 切换字幕；
* 手动重复。

---

## 原则 5：V0.1 不做大而全

V0.1 只验证一个问题：

> **逐句循环 + 双语字幕 + 真实原声，能不能明显提升精听体验。**

---

# 八、V0.1 产品目标

V0.1 的目标不是做成完整语言学习平台。

唯一目标：

> **用户能够导入一段真实英文内容，然后舒服地逐句精听。**

如果这个体验成立，再增加：

* 单词学习；
* AI 分析；
* 听写；
* 错词；
* SRS；
* 学习统计。

# 十、字幕处理

存在三种情况。

## 情况 A：已有英文字幕

优先使用现成字幕。

系统获取：

```text
text
start_time
end_time
```

然后进入：

**字幕整理 → 切句。**

---

## 情况 B：有字幕，但是字幕非常碎

例如：

```text
I think
this is
probably
a good idea
```

系统不能直接把它们当成四句话。

需要合并为：

```text
I think this is probably a good idea.
```

最终：

```text
start = 第一段字幕开始时间
end = 最后一段字幕结束时间
```

---

## 情况 C：没有字幕

V0.1 对本地媒体支持：

**Whisper 自动转录。**

YouTube 无字幕内容可以暂时不作为 V0.1 的强保证范围。

V0.2 再增强。

# 十一、核心数据结构

每个视频或音频叫一个：

## Media

```json
{
  "id": "media_001",
  "title": "Example Video",
  "source_type": "youtube",
  "source_url": "...",
  "duration_ms": 620000,
  "language": "en"
}
```

每句话叫一个：

## Sentence

```json
{
  "id": "sentence_001",
  "media_id": "media_001",

  "index": 1,

  "start_ms": 12420,
  "end_ms": 16850,

  "english": "I think this is actually a really good idea.",

  "chinese": "我觉得这其实是一个非常好的主意。"
}
```

V0.1 最核心的数据其实只有：

```text
start
end
english
chinese
```

# 十二、句子切分逻辑

V0.1 不追求完美 NLP。

使用：

**字幕时间 + 标点 + 停顿 + 长度限制**

完成即可。

优先级：

## 规则 1：标点判断

检测：

```text
.
?
!
```

如果出现明显结束标点：

优先判断为句子结束。

---

## 规则 2：停顿判断

如果两个字幕片段之间存在明显停顿：

例如：

```text
> 500～800ms
```

可以作为句子边界候选。

具体阈值后续通过实际素材调整。

---

## 规则 3：长度保护

避免一句话过长。

例如：

```text
推荐长度：

2～8 秒
```

允许：

```text
1～12 秒
```

超过一定长度后：

寻找最近的自然停顿进行拆分。

---

## 规则 4：过短合并

例如：

```text
Yeah.
```

只有 0.6 秒。

如果前后语义连续，可以考虑和相邻句子合并。

V0.1 可以先不做复杂语义合并。

# 十四、播放控制

播放器维护当前状态：

```text
currentSentence
```

例如：

```text
start = 12.42
end = 16.85
```

点击播放：

```text
seek(12.42)
play()
```

程序持续监听当前播放时间。

当：

```text
currentTime >= 16.85
```

如果循环还没完成：

```text
seek(12.42)
```

继续播放。

如果已经完成：

根据用户设置：

```text
停止
```

或者：

```text
进入下一句
```



# 二十一、中文翻译

流程：

```text
英文字幕
 ↓
先完成句子合并
 ↓
完整句子
 ↓
翻译
```

不要逐字幕碎片翻译。

例如错误方式：

```text
It's not like
→ 它不像

I don't want
→ 我不想

to do it
→ 做它
```

正确：

```text
It's not like I don't want to do it.

↓

并不是说我不想这么做。
```

# 三十四、长期产品愿景

长期愿景不是：

> “做一个更好用的视频播放器。”

而是：

> **建立用户的个人听力模型。**

系统逐渐知道：

```text
哪些单词你认识但听不出来

哪些连读你容易听错

哪些口音你不熟悉

哪些语速你容易掉信息

哪些表达你需要重复很多次
```

最终：

```text
普通英语内容
 ↓
AI 分析用户听力能力
 ↓
自动选择最适合练习的句子
 ↓
个性化精听训练
```

这时候产品就从：

**工具**

变成：

**AI 听力教练。**

---

# 三十五、最终产品定义

ListenLoop 的核心不是：

**字幕播放器**

也不是：

**YouTube 下载器**

也不是：

**背单词 App**

而是：

> **一个把真实母语内容自动转换成个人精听训练课程的 AI 学习工具。**

它解决的核心问题是：

> **“我认识这些英语，但为什么听不出来？”**

核心能力只有四件事：

```text
真实原声
+
精准切句
+
反复听
+
逐步理解
```

V0.1 只需要把这四件事做到非常顺滑，就已经足够验证产品价值。
