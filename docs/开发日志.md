## 2026-09-23 · 三份设计产出：尚雯婕四步法 / 听伴与语音交互 / 闪卡管理与策略

### 1. 尚雯婕方法查证（新华网等四来源交叉印证）

四步法（一篇 20 分钟材料 = 一个周期）：**选材 → 听写 → 查证 → 背诵（同速）**。

- 选材标准是**语法工整、逻辑清晰**（新闻/访谈/演讲/播客），**明确排除影视剧、文学、诗歌**；且必须真感兴趣
- 听写：先通听 3~5 遍建立结构再落笔，听不出的先空着，写完对照原文
- 背诵：整篇整段背，**速度必须与原声同步** —— 这是分水岭（同速 = 不再经过中文转换）
- 走完 **10 篇** → 可当工作语言用
- 无环境变体：每天 **30 分钟"高效听"**（全神贯注，反对边做事边听）+ 30 分钟专注读

> [!WARNING]
> **发现现状名不副实**：App 里那张「尚雯婕 3 分钟限时精听法」实际是 3 道选择题快测，与该方法无关 —— 只是用了她的名字。已在 05 文档中明确记录并给出处理建议。

**缺口**：方法四步里，第②步**听写**与第④步**同速背诵**我们**完全没有**，而这两步恰是方法的灵魂。产出 `05_尚雯婕精听法产品化设计.md`：四阶段状态机 + 可量化完成判据 + 听写模式（LCS 词级 diff 三色标注）+ 同速背诵（ASR 相似度 + 时长比 [0.9,1.1]）+ 10 篇训练营。

### 2. 语音能力实测（技术前提，全部实测非推测）

| 能力 | 模型 | 调用方式 | 实测延迟 | 成本 |
| :--- | :--- | :--- | :--- | :--- |
| ASR | `mimo-v2.5-asr` | `/chat/completions` + `input_audio`（base64） | **0.60s** | 按 token |
| TTS | `mimo-v2.5-tts` | `/chat/completions` + `audio:{format,voice}` → base64 mp3 | 短句 **0.95~1.43s**、200 字符 **3.40s** | **限时免费** |

**三个坑**：① MiMo **没有**标准 `/v1/audio/transcriptions`（实测 404），语音必须走 chat 接口；② TTS 首次调用 **11.47s**（冷启动），需预热；③ 音色是白名单（冰糖/茉莉/苏打/白桦/Mia/Chloe/Milo/Dean）。

网关侧也已有 `voice-tts`（MiMo → Edge-TTS 本地免费 → mistral）与 `voice-asr` 链，但需 PC；**App 直连 MiMo 才符合"手机独立"**。

产出 `06_AI陪练与语音交互设计.md`：命名候选（推荐**听伴**）+ 以"当前句"为中心的六动作（拆音变/讲语法/造句/**听写我**/**跟读评分**/加入闪卡）+ 语音落地方案（麦克风输入、分句 TTS 朗读）。

### 3. 闪卡管理与策略

## 2026-09-23 · 统一模型服务改为小米 MiMo（伴学 + 翻译，手机彻底脱离 PC）

**决策（郭老师拍板）**：App 内所有用到模型的地方统一换成小米 MiMo flash。

| 项 | 值 |
| :--- | :--- |
| Base URL | `https://api.xiaomimimo.com/v1` |
| 模型 | `mimo-v2.6-flash` |
| 回退链 | `mimo-v2.6-flash` → `mimo-v2.6-pro` → `mimo-v2.5`（同厂同 key 只换档位） |

- 英语伴学 → 7.5s，`Can I pick it up for you?` 的连读／弱读／闪音拆解准确

**代码落地**：

- `app_preferences.dart`：新增 `kDefaultMimo*` 常量；`kDefaultTranslation*` 与 `kDefaultTutor*` 全部改指 MiMo；翻译 key 与伴学 key 共用同一个预填值

  1. 通过真机设备流式管道，直接调用 Android 底层 `/system/bin/unzip -p` 将 82MB `audio.m4a` 与 `cover.jpg` 流式解压落盘至应用沙箱，杜绝 Dart 堆内存 OOM 风险。

## 2026-09-16 深夜（后）· Phase 3A 视频模式 · 真机可行性验证通过

**目标**：在真机上证明 Video Mode 的两块基石——① B站播放器能在 `webview_flutter` 里正常嵌入播放；② `<video>` 元素位于顶层文档，可用注入 JS 直接读写 `currentTime` 完成逐句 seek（**无需 iframe 重载**）。

### 侦察 + spike（宿主机 Playwright）
- `player.bilibili.com/player.html` 可达；`<video>` 为 MSE blob，**在顶层文档**（非 iframe）→ 可注入 JS。
- seek 延迟 5–745 ms（中位 ~250ms），系统精度偏差 ~+0.23s；`playbackRate` 可设。**结论：3B 走 `video.currentTime` 注入，不走重载。**

### App 落地
- 依赖：`webview_flutter ^4.14.1` + `webview_flutter_android ^4.14.1`。
- **`lib/models/video_source.dart`**：`VideoSource{provider,bvid,page,cid?,offsetMs=0}`，`playerUrlAt(lessonMs)` 生成 player URL，`toJson`/`tryFromJson`。

## 2026-09-24 · 手机端自足化收口：中继搬进 Termux + F-Droid 三件套开机自启

- **为什么做**：依赖审计显示唯一 PC 依赖 = YouTube 制课（AI 伴学/翻译走公网 MiMo、B 站 App 内自解析）——"电脑不在身边应用就废了"精确等于"YouTube 制课不可用"，只改这一处。
- **架构**：中继住进手机 Termux `127.0.0.1:8793`，HTTP 契约与 PC 版逐字一致（`/ping` `/resolve`，另加 `/diag` `/probe` `/exec`），**App 侧代码与配置零改动**（同契约同端口的可互换实现）。
- **反机器人已解**：yt-dlp 2026.08 起 YouTube 挑战必须由外部 JS 运行时解 → 手机 Node v24 + `--js-runtimes node` 即可；7 种 `player_client` 逐个实测全灭（换 client 绕不过），强制 `web` 反而失败；**不需要搬运 bgutil PO-token 服务**（PC 那份含 183MB 原生模块，不适合安卓）。
