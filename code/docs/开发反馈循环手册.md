## 一、三条通道（先选对通道，再动手）

| 通道 | 干什么用 | 典型耗时 | 命令 |
| :--- | :--- | :--- | :--- |
| **A. 真机 Hot Reload** | 改 UI / widget / 交互，验证真实 Android 表现 | 1~5 秒 | `flutter run -d <设备ID>` 后按 `r` |
| **B. 独立 Preview 入口** | 只看一个组件，不进 App、不碰数据库/ASR/音频 | 1~5 秒 | `flutter run -t lib/dev/reading_preview.dart` 后按 `r` |
| **C. 局部 Widget Test + Golden** | 自动抓 paint 断言、防视觉回归 | 3~15 秒 | `flutter test test/widgets/xxx_test.dart --no-pub` |

**判断口诀**：
- 改的是**界面** → A 或 B；
- 改的是**渲染/布局/会不会崩** → C（不用等真机）；
- 改的是**原生/依赖/pubspec/资源** → 才需要重新 `flutter run`；
- 只有**要发布**才 `flutter build apk`。

## 二、通道 A：真机 Hot Reload（默认工作流）

### 起步

```powershell
$env:PATH = "D:\flutter\bin;D:\android-sdk\platform-tools;$env:PATH"

adb devices          # 无线调试连上后，设备会出现在这里
flutter devices

flutter run -d <设备ID>          # 首次会编译+安装，慢一次就够
```

**关键：启动后别退出这个终端。** 手机上导航到你要改的页面，然后：

1. 改 Dart 文件，保存；
2. 在 `flutter run` 的终端里敲小写 **`r`**（热重载）；
3. 手机上立刻变。

终端会打印：

```
Performing hot reload...
Reloaded 1 of 448 libraries in 978ms.
```

### `r` / `R` / 重新 `flutter run` 怎么选

| 操作 | 键 | 耗时 | 保留页面状态 | 什么时候用 |
| :--- | :--- | :--- | :--- | :--- |
| Hot Reload | `r` | 1~5s | 通常保留 | 改颜色/边框/布局/普通逻辑 |
| Hot Restart | `R` | 3~15s | 不保留 | 改了 `initState()`、`main()`、全局 static 初始化 |
| 重新 `flutter run` | 停止后重跑 | 数十秒~数分钟 | 不保留 | 改了 Kotlin/Java、Manifest、Gradle、插件注册、pubspec/assets |

⚠️ **热重载不会重跑 `initState()` 和 `main()`** —— 「代码改了界面没变」十有八九是这个原因，按 `R` 再看。

### 顺手截图真机画面

```powershell
adb shell screencap -p /sdcard/Download/phrasing.png
adb pull /sdcard/Download/phrasing.png .
```

比在手机上截图再分享到电脑快得多。

## 三、通道 B：独立 Preview 入口（改组件最快）

### 为什么有它

改一个 widget 时，你**不想**为了看一眼就启动整个 App：数据库、讯飞 ASR、
音频服务、课包加载，全都跟这个改动没关系，却让启动慢、让导航麻烦。

`lib/dev/reading_preview.dart` 是一个**独立入口**：只喂固定数据，
不初始化 sqflite / ASR / 音频。

```powershell
flutter run -d <设备ID> -t lib/dev/reading_preview.dart
# 改 lib/widgets/lesson_reading_document.dart → 保存 → 按 r
```

进去以后可以现场调：字号滑杆、宋体/仿宋切换、模拟错词、下一句。

### 现有 Preview 入口

| 入口 | 预览什么 |
| :--- | :--- |
| `lib/dev/reading_preview.dart` | 读页整篇课文（真实 69 句课包数据） |

### 加新组件的 Preview

1. 新建 `lib/dev/<组件>_preview.dart`；
2. `main()` 里 `runApp` 一个能切换状态的页面；
3. 把要预览的组件抽成**只吃参数、不碰业务**的 widget（见下面「四层」）。

数据不够用时，用 `assets/data/dev_preview_sentences.json` 这类 fixture
（本仓已有一份真机课包导出的 69 句真实课文）。

## 四、通道 C：局部 Widget Test + Golden

### 为什么它能替代肉眼

2026-10-20 真机出过一个 bug：读页只显示一句、其余大片空白。
根因是 `BoxDecoration` 同时给了 `borderRadius` 和 `width: 0` 的
`BorderSide`（hairline）⇒ Flutter 在 **paint()** 阶段抛断言 ⇒
那一行整行画不出来。

这类 bug 的特点：
- build / layout 都正常 ⇒ 只测「Widget 存在」的断言**抓不到**；
- 只在真机上肉眼可见 ⇒ 反馈循环 3~4 分钟。

而 `flutter test` 会真实执行 build → layout → **paint**，所以它能自动抓到。

### 三个断言各有分工（要组合用）

```dart
// ① 捕获 paint/build/layout 阶段抛出的异常（hairline bug 就是这里抓到的）
expect(tester.takeException(), isNull);

// ② 确认渲染盒不是零尺寸（没塌缩）
expect(tester.getSize(find.byKey(key)).height, greaterThan(0));

// ③ 逐像素比对，防视觉回归
await expectLater(find.byKey(key), matchesGoldenFile('goldens/xxx.png'));
```

⚠️ `find.text('整句话')` 在 ruby 排版下**匹配不到** —— 排版是逐字 `Text`，
只能按单字找（`find.text('看')`）。

⚠️ `SliverList` 是**懒加载**的：滚到第 46 句时第 1 句早就不在树里了。
「首句不在树里」不是 bug，是正常行为。

### 现成的读页回归测试

```powershell
flutter test test/widgets/reading_document_paint_test.dart --no-pub
```

含 4 个用例：整课多句渲染、窄屏 280px 不崩、当前句在中间时邻句也渲染、
golden 像素基线。

**已验证**：把代码改回 `width: isCurrent ? 2 : 0`，测试立刻红并精确指出
`hairline border ... can only be drawn when BorderRadius is zero or null`。

### golden 的规矩

- **建立基准**：`flutter test <file> --update-goldens`（只在新设计确认后跑一次）
- **日常比对**：`flutter test <file>`（**不要**加 `--update-goldens`，
  否则每次改坏 UI 都自动更新基准，golden 就失去防回归意义）
- **中文字体坑**：`flutter_test` 默认用 Ahem 测试字体，中文会显示成方块。
  只验证边框/背景/间距没问题；要验证真实字形，得用 `FontLoader` 加载
  `assets/fonts/SongTi.ttf`，并保证 widget 的 `fontFamily` 一致。
- **基准图统一在 Windows + 固定 Flutter 版本生成**，不要拿去和 Linux CI 逐像素比。

## 五、只跑受影响的测试（别每次跑全套）

```powershell
.\tool\test-changed.ps1
```

按**目录约定**保守裁剪（本仓 `lib/` 与 `test/` 顶层一一对应）：

- 改了 `lib/widgets/...` ⇒ 跑 `test/widgets/`
- 改了 `lib/screens/...` ⇒ 跑 `test/screens/`
- 改了 `test/xxx_test.dart` ⇒ 跑那一个文件
- 改了共享层（`theme/` `utils/` `l10n/` `data/` `interaction/`）⇒ **跑全量**
- 改了 `pubspec.yaml` / 原生代码 ⇒ **跑全量**

⚠️ 这是按目录的**保守裁剪**，不是精确的 Dart import 依赖分析。
跨目录导入仍可能漏测 ⇒ **全量测试仍是提交前/里程碑前的最终关卡**。

```powershell
.\tool\test-changed.ps1 -Full              # 强制全量
.\tool\test-changed.ps1 -UpdateGoldens     # 更新 golden 基准（慎用）
```

### 三档测试习惯

| 什么时候 | 跑什么 |
| :--- | :--- |
| 开发内循环（改一个 widget） | 那一个测试文件 |
| 提交前 | `.\tool\test-changed.ps1`（受影响范围） |
| 里程碑 / 发版前 | `flutter test` 全量 + 少量真机集成测试 |

**别追覆盖率百分比。** 每修一次 bug，就把导致它的输入存成一个回归用例 ——
这比刷覆盖率有效得多。

## 六、Flutter 没有「单独编译一个 Widget DLL」这回事

先说清楚，免得白找：

- **Feature 目录**：只是组织代码，**不能**让单个 widget 独立运行；
- **Dart / Flutter package**：能隔离编译与测试，但要配套入口或测试宿主；
- **独立 `main()` 入口**：**最值得先做** —— 只启动你想看的东西；
- **RepaintBoundary**：只隔离重绘与指定截图区域，**不能**独立启动；
- **Golden Test**：能离屏渲染并出 PNG。

Hot Reload 是**增量编译受影响的 Dart library** 并重建运行中的 widget 树，
不是「只执行某一个 widget 的 build()」。

**所以 Phrasing 现在不该拆 package。** 30 多个模块还没到那个规模。
先把热重载、独立 Preview、Paint 回归测试三件事变成日常习惯，
再决定要不要拆 UI package。

## 七、要拆的话，四层边界怎么划

```
第 1 层  纯 UI（Presentation View）
        吃普通 Dart 数据，出 Widget，事件靠 callback 往外传。
        不碰 sqflite / ASR / 文件系统，不在 initState 里起业务服务。

第 2 层  交互状态（Controller / Application）
        管当前句、评分状态、播放状态。依赖抽象接口，不依赖讯飞/数据库实现。

第 3 层  设备能力接口（Ports）
        AsrPort / AudioPort / CourseRepository —— 测试里注入 Fake。

第 4 层  平台实现（Infrastructure）
        讯飞 SDK、真实音频、sqflite、本地课包。只在真机/集成测试里验证。
```

**判定标准只有一条**：能不能用固定输入，在 `testWidgets()` 里**直接构造**
这个 widget？

必须先起数据库、加载课包、初始化音频才能构造 ⇒ 这块 UI 还没达到
「独立预览」的要求。

## 八、常见坑速查

| 症状 | 真因 | 怎么办 |
| :--- | :--- | :--- |
| 代码改了界面没变 | 热重载不重跑 `initState()`/`main()` | 按 `R`（Hot Restart） |
| 一整行/整块不显示 | paint() 断言（如 hairline + 圆角） | `flutter test` 的 `takeException()` 会抓到 |
| 改完必须重新装机 | 改了原生/依赖/assets | 那是 A 通道管不了的，重跑 `flutter run` |
| golden 全红但界面看着对 | 字体不同（Ahem 测试字体） | `FontLoader` 加载 SongTi |
| `flutter` 找不到 | PATH 没带 SDK | `$env:PATH = "D:\flutter\bin;..."`，或设 `$env:FLUTTER_ROOT` |
| `flutter test` 慢 | 跑了全套 | `.\tool\test-changed.ps1`，或 `--plain-name` 筛单个用例 |
